## 二、三个阻塞级决策（必须先做）

### 决策 1：战斗系统类型

这是影响最深远的设计决策，直接决定：网络同步复杂度、Tick Rate 需求、客户端预测实现方式、技能系统设计。

| 选项 | 代表游戏 | 优势 | 劣势 | 技术难度 |
|------|----------|------|------|----------|
| **A. 实时动作** | Surviv.io, Diep.io | 刺激、直觉、适合 PvP | 网络同步最难、延迟敏感 | ★★★★★ |
| **B. 实时+技能冷却** | Albion Online, MOBA | 有策略深度、PvP 观赏性强 | 需要大量技能平衡 | ★★★★ |
| **C. 半回合制** | Dofus, Wakfu | 网络要求低、策略性强 | 节奏慢、不适合大规模 PvP | ★★★ |
| **D. 自动战斗+策略** | AFK Arena, Raid | 开发最快、适合手机 | 缺乏操作感、PvP 深度低 | ★★ |

**我的建议**：选 **B（实时+技能冷却）**
- 理由：你的世界观有丰富的种族/阵营差异，需要技能系统来体现；实时操作保证 PvP 刺激感；技能冷却降低了对帧精确同步的要求（比纯动作游戏宽容）
- 参考：类似 Albion Online 的俯视角 + 技能栏模式，但简化为 4-6 个技能

---

### 决策 2：视角与画面风格

| 选项 | 代表 | 优势 | 劣势 |
|------|------|------|------|
| **A. 俯视角（Top-down）** | Surviv.io, Albion | 最适合多人 PvP、地图设计自由 | 角色表现力有限 |
| **B. 45° 等距（Isometric）** | Dofus, 暗黑2 | 视觉丰富、有深度感 | 碰撞检测复杂、美术成本高 |
| **C. 横版（Side-scroll）** | MapleStory | 角色表现力强 | 不适合大地图探索和多人混战 |

**我的建议**：选 **A（俯视角）**
- 理由：技术实现最简单（2D 碰撞检测直接用矩形/圆形）；最适合多人 PvP 混战场景；地图设计自由度最高；PixiJS 渲染效率最优
- 美术风格建议：**像素风（Pixel Art）**——制作速度快、独立游戏辨识度高、社区有大量免费/低价素材可用于原型阶段

---

### 决策 3：MVP 范围（v0.1 — 4 周可玩原型）

**目标**：用最少的工作量验证"多人 PvP 争夺资源"这个核心循环是否有趣。

**MVP 包含**：
- [ ] 1 个地图（简化版裂隙之桥，小型竞技场）
- [ ] 2-8 人同时在线
- [ ] 角色移动 + 基础攻击（1 个普攻 + 2 个技能）
- [ ] 1 个资源点（源石碎片），占领后得分
- [ ] 简单的血条 + 死亡重生
- [ ] 无阵营、无种族、无装备（纯操作验证）
- [ ] 基础 UI：血条、技能冷却、得分板

**MVP 不包含**：
- ❌ 阵营系统
- ❌ 种族选择
- ❌ 装备/成长
- ❌ NPC/剧情
- ❌ 多地图
- ❌ 美术（用色块/简单几何图形代替）

## 三、推荐路线图

### Phase 0：决策与架构（1 周）

```
目标：做出三个关键决策 + 写技术架构文档
```

- [ ] 确认战斗系统类型
- [ ] 确认视角与美术风格
- [ ] 定义 MVP 范围
- [ ] 编写技术架构文档：
  - WebSocket 消息协议（MessagePack schema）
  - 数据库表结构
  - 前端状态管理架构
  - 游戏循环（Game Loop）设计

### Phase 1：技术原型（2-3 周）

```
目标：证明"多人实时同步"技术可行
```

- [ ] 搭建前端项目（Vite + React + PixiJS）
- [ ] 搭建后端项目（Go + Gorilla WebSocket）
- [ ] 实现基础连接：客户端连接服务器，分配 ID
- [ ] 实现角色移动同步：WASD 移动，其他玩家可见
- [ ] 实现客户端预测 + 服务器校正
- [ ] 实现实体插值（其他玩家平滑移动）
- [ ] 部署到 Vercel + HF Spaces，验证延迟

### Phase 2：核心循环原型（2-3 周）

```
目标：证明"PvP 争夺资源"玩法有趣
```

- [ ] 实现基础战斗（攻击、受伤、死亡、重生）
- [ ] 实现 2-3 个技能（不同冷却和效果）
- [ ] 实现资源点（源石碎片）占领机制
- [ ] 实现简单计分系统
- [ ] 实现基础 UI（血条、技能栏、计分板）
- [ ] 邀请 3-5 个朋友测试，收集反馈

### Phase 3：垂直切片（4-6 周）

```
目标：一个完整的"小游戏"体验
```

- [ ] 角色创建（选阵营 + 选种族）
- [ ] 2-3 个区域（主城 + 争夺区 + 资源区）
- [ ] 基础成长系统（等级 + 简单装备）
- [ ] 阵营积分系统
- [ ] 像素风美术替换色块
- [ ] 基础音效
- [ ] 新手引导

### Phase 4：内容填充与软发布（持续）

```
目标：可以公开让陌生人玩
```

- [ ] 完整的 10 个区域
- [ ] NPC 与任务系统
- [ ] 完整技能树
- [ ] 虚空潮汐事件
- [ ] 排行榜
- [ ] 商城（外观）
- [ ] SEO + 社区运营

## 四、风险与建议

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| HF Spaces WebSocket 不稳定 | 中 | 高 | Phase 1 就验证；备选 Railway/Fly.io |
| 一个人做不完 | 高 | 高 | 严格控制 MVP 范围；先验证再扩展 |
| 核心循环不好玩 | 中 | 致命 | Phase 2 尽早测试；愿意 pivot |
| 美术资源不足 | 中 | 中 | 先用程序化图形；后期找像素画师 |
| 延迟过高影响体验 | 低 | 高 | 客户端预测 + 实体插值已在架构中 |
