# Arthas 路线图

> 更新：2026-05-28  
> 定位：加密版 AirDrop + 临时聊天 — 安全交换信息，用完即走  
> 架构：事件驱动，服务器纯中转（零知识）  
> 加密：Web Crypto API + AES-256-GCM  
> 技术栈：Go · WebSocket · MessagePack · React · Vite

---

## 产品定位

```
Arthas ≠ Signal 的替代品（Signal 做长期通信）
Arthas = "我需要和某人安全地交换一些信息，用完即走"

核心价值：
  • 无需注册，打开即用
  • 端到端加密，服务器零知识
  • 阅后即焚，房间销毁密文消失
  • 轻量自托管，一行命令部署
```

## Phase 8：安全升级 ✅ 已完成

```
目标：从"够用的安全"到"专业级安全"
完成日期：2026-05-20
```

- [x] **加密 Typing 状态** — AES-256-GCM 加密输入状态，消除服务器元数据观察
- [x] **Ed25519 消息签名** — 防止服务器伪造消息，接收方可验证发送者身份
- [x] **Canonical JSON 序列化** — 跨客户端一致的签名字节计算（Web + CLI 互操作）
- [x] **公钥广播与 TOFU 信任** — 加入房间时广播公钥，首次信任模型
- [x] **签名验证 UI** — Web 端 ✓ 图标（验证通过）/ ⚠️ 图标（验证失败）
- [x] **CLI 签名集成** — CLI 发送签名消息 + 验证收到消息的签名
- [x] **跨客户端互操作测试** — Web 签名 → CLI 验证 / CLI 签名 → Web 验证
- [x] **属性测试覆盖** — 14 个属性测试验证加密/签名/序列化的正确性

**安全属性：**
- 服务器无法伪造消息（Ed25519 签名检测篡改）
- 服务器无法观察谁在输入（typing 状态加密）
- TOFU 信任模型（首次收到的公钥被信任，密钥变更时警告）
- 向后兼容（旧客户端发送的无签名消息正常显示）

**后续迭代备忘：**
- publicKeyMap LRU 淘汰（大规模/长期房间场景）
- SAS 验证（Short Authentication String，从 TOFU 升级为可验证信任）
- 密钥轮换（踢人后新密钥，被踢成员无法解密后续消息）

## 战略原则

### ✅ 坚持做的

| 原则 | 理由 |
|------|------|
| 无需注册 | 核心卖点，降低使用门槛 |
| 阅后即焚 | 核心卖点，差异化定位 |
| 服务器零知识 | 安全基石，不可妥协 |
| 轻量简洁 | 用完即走的工具，不是社交平台 |
| 开源透明 | 建立信任，安全可审计 |

### ❌ 不做的

| 反模式 | 理由 |
|--------|------|
| 用户注册/账号体系 | 杀死"无需注册"核心价值 |
| 消息持久化/历史记录 | 杀死"阅后即焚"核心价值 |
| 原生 App (iOS/Android) | PWA 足够，维护成本太高 |
| 过度工程化后端 | 它就是个 relay，保持简单 |
| 急着加 Double Ratchet | 对临时聊天收益不大，复杂度极高 |
| 社交功能（好友/群组/动态） | 偏离定位，变成另一个 IM |
