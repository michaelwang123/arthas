# Requirements: 房间密码保护 + 阅后即焚 (Phase 6.2 + 6.4)

## Overview

为 Arthas 添加两个安全/隐私增强功能：
1. **房间密码保护** — 防止分享码泄露后被陌生人加入
2. **阅后即焚模式** — 消息阅读后自动从屏幕消失

两个功能都是轻量级改动，密码保护需要前后端协同，阅后即焚纯前端实现。

## Functional Requirements

### 1. 房间密码保护

- 1.1 创建房间时**可选**设置密码（留空 = 无密码，与现有行为完全一致）
- 1.2 密码长度限制 4-20 字符（前端 + 后端双重验证）
- 1.3 设置密码的房间，加入时需要输入正确密码
- 1.4 密码验证在服务端进行（防止客户端绕过）
- 1.5 密码错误时返回明确错误提示（"密码错误"，错误码 E006）
- 1.6 密码在服务端以 SHA-256 hash 存储在内存中（房间销毁时消失，不持久化）
- 1.7 创建者自己不需要输入密码（创建即加入）
- 1.8 分享码中不包含密码（密码需要通过其他渠道告知）
- 1.9 Home 页面创建房间区域增加**可选的**"房间密码"输入框（默认隐藏，通过"🔐 设置密码"链接展开）
- 1.10 Home 页面加入房间区域增加**可选的**"房间密码"输入框
- 1.11 ChatRoom header 中显示 🔐（有密码）或 🔒（无密码）图标区分
- 1.12 无密码房间的行为与当前完全一致（向后兼容，不影响现有用户）

### 2. 阅后即焚模式

- 2.1 创建房间时可选开启"阅后即焚"模式
- 2.2 阅后即焚模式下，每条消息显示后 N 秒自动从屏幕消失（默认 30 秒）
- 2.3 消失动画：淡出 + 高度收缩（200ms，避免短时间模式下"还没看完就消失"的感觉）
- 2.4 消失后消息从本地 messages 数组中移除（不可恢复）
- 2.5 自己发送的消息也会消失（所有人一视同仁）
- 2.6 系统消息（加入/离开）不消失
- 2.7 阅后即焚是纯客户端行为，服务器不参与（服务器本来就不存储消息）
- 2.8 ChatRoom header 中显示 ⏱️ 图标表示阅后即焚模式
- 2.9 每条消息下方显示倒计时进度条（剩余时间可视化）
- 2.10 创建房间时可选择消失时间：10秒 / 30秒 / 60秒 / 5分钟
- 2.11 阅后即焚模式信息包含在分享码中（加入者自动获知模式和时间）
- 2.12 加入页面解析分享码后，如果包含阅后即焚信息，在加入按钮旁显示"⏱️ 阅后即焚 30秒"提示

### 3. 协议扩展

- 3.1 `MSG_CREATE_ROOM` data 新增可选字段 `password`（string，空字符串表示无密码）
- 3.2 `MSG_CREATE_ROOM` data 新增可选字段 `ephemeral`（number，0 表示关闭，>0 表示消失秒数）
- 3.3 `MSG_JOIN_ROOM` data 新增可选字段 `password`（string）
- 3.4 `MSG_ROOM_JOINED` data 新增字段 `hasPassword`（boolean）和 `ephemeral`（number）
- 3.5 新增错误码 `E006`："密码错误"
- 3.6 服务端 Room 结构新增 `Password string` 和 `Ephemeral int` 字段

## Non-Functional Requirements

- 4.1 密码不通过网络以明文传输 — 客户端发送密码的 SHA-256 hash（防止中间人窃取明文密码）
- 4.2 不引入新的 npm/Go 依赖（SHA-256 使用 Web Crypto API / crypto/sha256）
- 4.3 阅后即焚的倒计时使用 CSS animation（GPU 加速，不阻塞主线程）
- 4.4 消失动画尊重 prefers-reduced-motion
- 4.5 所有新增 UI 使用 Tailwind CSS 暗色主题
- 4.6 密码输入框使用 `type="password"` 隐藏输入
- 4.7 密码长度验证（4-20 字符）在前端和后端双重执行

## Constraints

- 前端 + 后端都需要修改
- 不引入新依赖
- 密码保护是可选的（向后兼容，不设密码的房间行为不变）
- 阅后即焚是可选的（默认关闭）
- 分享码格式需要扩展以包含 ephemeral 信息
