# Requirements: Phase 5 体验打磨（第一批）

## Overview

将 Arthas 从"能用"提升到"想用"。聚焦三个高 ROI 改进：连接状态横幅、响应式移动端适配、消息通知。

## Functional Requirements

### 1. 连接状态横幅

- 1.1 当 WebSocket 断开时，在聊天室顶部显示"连接中断，正在重连..."横幅
- 1.2 横幅使用醒目的黄色/橙色背景，带动画脉冲效果
- 1.3 重连成功后横幅短暂显示"已重连"（绿色），2 秒后平滑收起
- 1.4 横幅出现/消失使用平滑高度过渡动画（无布局跳动）
- 1.5 横幅消失后不占用任何空间
- 1.6 首次加载时，给予 1.5 秒连接宽限期：如果 1.5 秒内连接成功则不显示横幅（避免快速网络下的闪烁）
- 1.7 宽限期结束后仍未连接，则显示横幅
- 1.8 快速断开/重连切换时（2 秒内），取消前一个定时器，以最新状态为准
- 1.9 Home 页面已有连接状态指示器，无需修改

### 2. 响应式/移动端适配

- 2.1 成员列表在移动端（< 768px）改为可滑出的抽屉式面板
- 2.2 提供一个按钮（在 header 中）触发成员列表抽屉的显示/隐藏
- 2.3 抽屉打开时有半透明遮罩层，点击遮罩关闭抽屉
- 2.4 抽屉打开时按 Escape 键可关闭
- 2.5 抽屉打开时焦点锁定在抽屉内（Tab/Shift+Tab 循环），关闭后焦点回到触发按钮
- 2.6 抽屉打开时主内容区域禁止滚动（body scroll lock）
- 2.7 输入框在移动端适配虚拟键盘（使用 `dvh` 单位，带 `vh` fallback）
- 2.8 按钮和可点击元素最小触摸区域 44x44px
- 2.9 Header 中的房间 ID 在移动端截断显示（避免溢出）
- 2.10 分享码区域在移动端仅显示"复制分享码"按钮，不显示完整文本

### 3. 消息通知

- 3.1 收到新消息时播放提示音（短促、不刺耳）
- 3.2 提供静音按钮（在 header 中），状态持久化到 localStorage
- 3.3 静音仅控制声音，不影响桌面通知（用户可能静音但仍想看到视觉提醒）
- 3.4 当页面不在前台时（document.hidden === true），使用 Notification API 推送桌面通知
- 3.5 通知内容显示发送者昵称，不显示消息内容（保护隐私）
- 3.6 首次使用时请求通知权限，时机为用户首次在聊天室内交互（点击/输入）后
- 3.7 自己发送的消息不触发通知音效和桌面通知
- 3.8 AudioContext 必须在用户手势事件中初始化（满足 iOS Safari 自动播放策略）

## Non-Functional Requirements

- 4.1 所有新增 UI 组件使用 Tailwind CSS，与现有风格一致（暗色主题 gray-800/900）
- 4.2 不引入新的 npm 依赖（音效使用 Web Audio API 合成）
- 4.3 移动端适配不影响桌面端现有布局
- 4.4 动画使用 CSS transition/animation，不使用 JS 动画库
- 4.5 尊重 `prefers-reduced-motion` 媒体查询：用户开启"减少动态效果"时禁用所有动画
- 4.6 所有交互元素有适当的 aria-label 或语义化标签
- 4.7 连接状态横幅使用 `role="alert"` + `aria-live="polite"` 确保屏幕阅读器播报
- 4.8 `dvh` 单位需提供 `vh` fallback（兼容 Chrome < 108, Firefox < 108）
- 4.9 动画 keyframes 定义在 `tailwind.config.js` 的 `extend` 中（与项目零自定义 CSS 模式一致）
- 4.10 横幅出现/消失不产生 Cumulative Layout Shift（CLS = 0）

## Constraints

- 仅修改 `arthas-client/src/` 目录和 `tailwind.config.js`
- 不修改后端代码
- 不修改 Home 页面
- 不做 PWA（Phase 5 第二批）
- 需要 Tailwind CSS ≥ 3.4（项目当前 3.4.17 ✓）
