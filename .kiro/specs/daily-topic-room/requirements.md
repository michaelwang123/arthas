# Requirements — 每日话题房间 (Daily Topic Room)

## Overview

在 Arthas Hub 中增加"每日话题"功能：服务器每天自动创建一个带话题的公开房间，于次日 UTC 0:00 过期后自动销毁。给 Hub 用户一个"每天来看看"的理由，提升 Hub 回访率和活跃度。

## Functional Requirements

### FR-1: 话题池管理
- FR-1.1: 服务器维护一个内置话题池（Go embed JSON），包含 30+ 条预设话题
- FR-1.2: 话题池中每条话题包含：标题（title）、描述（description）、标签（tags）
- FR-1.3: 话题选择使用确定性索引（基于日期计算），同一天始终选择同一话题，重启不影响
- FR-1.4: 话题池中中英文混合编排（部分中文话题、部分英文话题），不做服务端语言检测

### FR-2: 自动创建房间
- FR-2.1: 服务器启动时检查是否需要创建今日话题房间（幂等：同一 UTC 日期内只创建一次）
- FR-2.2: 每天 UTC 0:00（北京时间 8:00）自动创建新的话题房间，旧房间同时过期销毁
- FR-2.3: 房间过期时间固定为下一个 UTC 0:00（话题切换时间全球一致，房间寿命随创建时间而异）
- FR-2.4: 房间参数：公开（public=true）、无密码、不开阅后即焚
- FR-2.5: 房间标题格式："📅 {topic_title}"（话题标题本身已含主题描述）
- FR-2.6: 服务器为房间生成 AES-256 加密密钥并注册到 Hub（密钥公开，与 Hub 公开房间安全模型一致）
- FR-2.7: 创建时使用固定标签 `["daily-topic"]` + 话题自身标签
- FR-2.8: 每日话题房间不受 Hub maxRooms 容量限制（拥有保留位）

### FR-3: Hub 前端展示
- FR-3.1: Hub 首页置顶显示"今日话题"卡片（与普通房间视觉区分）
- FR-3.2: 今日话题卡片显示：话题标题、描述、参与人数、剩余时间倒计时
- FR-3.3: 今日话题卡片使用特殊样式（渐变边框 + 📅 图标 + 全宽布局）
- FR-3.4: 点击今日话题卡片直接加入房间（复用现有 Hub join 流程，无需特殊处理）
- FR-3.5: 卡片显示安全提示标记："🌐 公开房间"（提醒用户消息对所有参与者可见）

### FR-4: 生命周期管理
- FR-4.1: 话题房间过期后由现有的 `cleanupExpiredRooms` 机制自动销毁
- FR-4.2: 服务器重启后，调度器立即检查并创建新的今日话题房间（旧房间已随重启丢失，与 Arthas 临时性设计一致）
- FR-4.3: 每日话题房间在 Hub API 中标记为 `isDailyTopic: true`

## Non-Functional Requirements

### NFR-1: 性能
- NFR-1.1: 话题房间的创建不影响服务器启动时间（< 10ms 额外开销）
- NFR-1.2: Hub API 返回 `isDailyTopic` 字段不增加额外查询开销（字段已在 RoomListing 中）

### NFR-2: 可靠性
- NFR-2.1: 定时任务失败时记录错误日志（logger.Error），不影响服务器其他功能
- NFR-2.2: 调度器内置于服务器进程，不依赖外部 cron 服务
- NFR-2.3: 确定性索引保证同一天选择同一话题，不受重启、时钟漂移影响

### NFR-3: 可维护性
- NFR-3.1: 话题池可通过修改嵌入 JSON 文件扩展（重新编译即可）
- NFR-3.2: 可通过环境变量或 flag 禁用每日话题功能（`--disable-daily-topic` / `DISABLE_DAILY_TOPIC=true`）
- NFR-3.3: 调度器关键节点有日志输出（创建成功/失败、话题选择、过期时间）

### NFR-4: 兼容性
- NFR-4.1: 不修改现有 Hub API 响应结构（仅新增可选字段 `isDailyTopic`，`omitempty`）
- NFR-4.2: 旧版前端在不支持 `isDailyTopic` 时仍可正常显示房间（退化为普通公开房间）

### NFR-5: 可测试性
- NFR-5.1: 调度器支持时间注入（nowFunc），方便单元测试控制时间
- NFR-5.2: RoomCreator 接口解耦，可 mock 测试调度器逻辑

## User Stories

- **US-1**: 作为 Hub 用户，我打开 Hub 看到今日话题置顶，想参与讨论就点击加入
- **US-2**: 作为 Hub 用户，我每天来 Hub 都能看到不同的话题，觉得有新鲜感
- **US-3**: 作为服务器管理员，我可以通过 flag 禁用此功能或修改话题池
- **US-4**: 作为开发者，我可以通过注入 mock 时间函数测试调度器行为

## Out of Scope

- 用户投稿话题（后续迭代）
- 话题投票/评分系统
- 多时区支持（统一 UTC，全球同一时间切换话题）
- 历史话题归档页面（后续迭代）
- 话题房间的特殊聊天规则（与普通房间行为一致）
- 外部配置文件覆盖话题池（MVP 仅支持嵌入 JSON）
- 服务端语言检测/切换
