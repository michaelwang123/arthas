# Requirements: 消息回复与反应 (Phase 6.3 + 6.5)

## Overview

为 Arthas 加密聊天室添加消息回复（引用）和 emoji 反应功能。这两个功能是现代聊天应用的标配，能显著提升互动性。

核心约束：所有数据（引用内容、反应 emoji）都通过现有 E2EE 加密通道传输，服务器仍然零知识。

## Functional Requirements

### 1. 消息回复/引用

- 1.1 用户可以选择一条消息进行回复
- 1.2 桌面端：hover 消息时显示"回复"按钮（与复制按钮并列）
- 1.3 移动端：滑动消息气泡向右触发回复（swipe-to-reply，阈值 60px，左右对齐的消息都向右滑）
- 1.4 选择回复后，输入框上方显示"回复预览条"：显示被引用消息的发送者名称 + 内容摘要（最多 50 字符）
- 1.5 回复预览条有"✕"按钮可取消回复
- 1.6 发送带回复的消息时，加密载荷中包含被引用消息的稳定 ID 和明文摘要
- 1.7 接收方解密后，消息气泡顶部显示引用块（灰色背景 + 发送者名 + 内容摘要）
- 1.8 点击引用块滚动到原消息位置（如果原消息仍在视图中）
- 1.9 如果原消息已被滚动出 200 条缓冲区，引用块仍显示摘要但不可点击
- 1.10 系统消息不可回复
- 1.11 解密失败的消息不可回复
- 1.12 消息必须有跨客户端稳定 ID（`senderId:timestamp`），用于回复和反应的引用定位

### 2. 消息反应 (Reactions)

- 2.1 用户可以对任意非系统消息添加 emoji 反应
- 2.2 桌面端：hover 消息时显示"😊+"反应按钮，点击弹出快速反应面板
- 2.3 快速反应面板包含 6 个常用 emoji：👍 ❤️ 😂 😮 😢 🎉
- 2.4 点击面板中的 emoji 即发送反应
- 2.5 移动端：双击消息气泡弹出快速反应面板
- 2.6 每个用户对同一条消息只能有一个反应（点击同一 emoji 取消，点击不同 emoji 自动替换旧反应）
- 2.7 消息气泡下方显示反应汇总：emoji + 数量（如 👍2 ❤️1）
- 2.8 点击反应汇总中的 emoji 可以切换自己的反应（添加/取消）
- 2.9 反应数据通过加密通道传输（服务器只中转密文）
- 2.10 自己的反应高亮显示（蓝色边框）
- 2.11 切换反应 emoji 时，自动发送 remove 旧 + add 新（两条消息）
- 2.12 双击反应区域必须禁用浏览器双击缩放（`touch-action: manipulation`）
- 2.13 反应面板根据消息在视口中的位置动态定位（上方空间不足时显示在下方）
- 2.14 反应面板点击外部时关闭（与 emoji 选择器相同的 excludeRef 模式）

### 3. 协议扩展

- 3.1 新增消息类型 `MSG_SEND_REACTION`（0x07）：Client → Server
- 3.2 新增消息类型 `MSG_RELAY_REACTION`（0x19）：Server → Client
- 3.3 回复功能不需要新协议消息类型 — 引用数据嵌入在现有 `MSG_SEND_MESSAGE` 的加密载荷中
- 3.4 反应消息格式：`{ iv, ciphertext }` — 加密载荷解密后为 `{ stableId, emoji, action: 'add'|'remove' }`
- 3.5 服务器对反应消息的处理与普通消息相同：验证房间成员 → 广播给其他成员（不计入频率限制）

## Non-Functional Requirements

- 4.1 引用数据在加密载荷内部，服务器无法读取引用内容（零知识保持）
- 4.2 反应数据同样加密传输
- 4.3 不引入新的 npm/Go 依赖
- 4.4 回复/反应 UI 使用 Tailwind CSS 暗色主题
- 4.5 滑动回复手势不与浏览器原生滑动冲突（仅水平方向，阈值 60px，垂直滑动取消）
- 4.6 反应面板使用 prefers-reduced-motion 禁用动画
- 4.7 所有新增交互元素有 aria-label
- 4.8 稳定 ID 方案不需要后端改动（纯前端计算）

## Constraints

- 前端 + 后端都需要修改（新增协议消息类型）
- 不引入新的 npm/Go 依赖
- 加密载荷格式变更需向后兼容（旧客户端收到带引用的消息应能正常显示文本，忽略引用）
- 反应状态仅存在于客户端内存（房间销毁后消失，与消息一样阅后即焚）
- 稳定 ID 使用 `senderId:timestamp` 模式（同一发送者同一毫秒内不可能发两条消息）
